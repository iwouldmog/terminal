# Эмулятор командной оболочки UNIX

Практическая работа № 1 по дисциплине «Конфигурационное управление»,
вариант № 17.

## 1. Общее описание

Консольное приложение (CLI), имитирующее работу в командной строке
UNIX-подобной ОС. Реализовано на Python 3 без сторонних зависимостей.

Текущее состояние — **этап 2 (конфигурация)**: прототип ведёт диалог с
пользователем, принимает параметры командной строки и выполняет
стартовый скрипт. Команды `ls` и `cd` пока являются заглушками и
выводят своё имя и аргументы.

Структура репозитория:

```
.
├── Makefile            цели для запуска и тестирования
├── run.sh              скрипт запуска эмулятора
├── scripts/            скрипты ОС для тестирования эмулятора
├── startup/            стартовые скрипты эмулятора
├── src/                исходный код
│   ├── main.py         точка входа
│   ├── config.py       параметры командной строки
│   ├── shell.py        оболочка: REPL и стартовые скрипты
│   ├── line_parser.py  разбор строки на команду и аргументы
│   ├── commands.py     встроенные команды
│   └── errors.py       исключения и коды завершения
└── tests/              модульные тесты (unittest)
```

## 2. Функции и настройки

### Параметры командной строки

```
./run.sh [-h] [--vfs PATH] [--script PATH]
```

| Параметр        | Описание                                           |
|-----------------|----------------------------------------------------|
| `--vfs PATH`    | путь к физическому расположению VFS                |
| `--script PATH` | путь к стартовому скрипту                          |
| `-h`, `--help`  | справка по параметрам                              |

Значения можно задавать как `--vfs PATH`, так и `--vfs=PATH`.
При запуске выводится отладочная информация обо всех параметрах:

```
[debug] vfs: data/demo.zip
[debug] script: (not set)
```

### Приглашение к вводу

Приглашение содержит имя VFS — имя файла из `--vfs` без расширения
(`data/demo.zip` → `demo$ `). Без `--vfs` используется имя `vfs`.

### Стартовый скрипт

Текстовый файл (UTF-8) с командами эмулятора, по одной на строку.

- Команды выполняются последовательно; каждая строка выводится после
  приглашения, затем выводится результат — как в диалоге.
- Пустые строки пропускаются, `#` начинает комментарий.
- Строки с ошибками выводят сообщение и пропускаются.
- `exit` завершает эмулятор; если скрипт закончился без `exit`,
  продолжается диалог с пользователем.
- Если скрипт не удалось прочитать, эмулятор завершается с кодом 1.

Примеры скриптов лежат в каталоге `startup/`.

### Разбор команд

Строка разделяется на команду и аргументы по пробельным символам.
Пустые строки игнорируются. Слово, начинающееся с `#`, открывает
комментарий до конца строки.

### Команды

| Команда    | Описание                                                |
|------------|---------------------------------------------------------|
| `ls ...`   | заглушка: выводит `ls: args=[...]`                      |
| `cd ...`   | заглушка: выводит `cd: args=[...]`                      |
| `exit [N]` | завершает эмулятор с кодом `N` (по модулю 256); без     |
|            | аргумента — с кодом последней команды, как в bash       |

### Обработка ошибок

| Ситуация                      | Сообщение                                | Код |
|-------------------------------|------------------------------------------|-----|
| неизвестная команда           | `foo: command not found`                 | 127 |
| неверные параметры запуска    | сообщение `argparse` и справка           | 2   |
| скрипт не найден / не читается| `emulator: cannot read script '...'`     | 1   |
| нечисловой аргумент `exit`    | `exit: abc: numeric argument required`   | 1   |
| лишние аргументы `exit`       | `exit: too many arguments`               | 1   |
| Ctrl+C во время ввода         | ввод строки прерывается, работа идёт     | 130 |
| Ctrl+D (конец ввода)          | эмулятор завершается                     | —   |

Ошибки выводятся в stderr, после ошибки диалог продолжается.

### Основные функции (модули `src/`)

| Функция / класс             | Назначение                                  |
|-----------------------------|---------------------------------------------|
| `config.parse_args`         | разобрать параметры командной строки        |
| `config.print_config`       | отладочный вывод параметров                 |
| `config.vfs_name`           | получить имя VFS из пути                    |
| `line_parser.parse_line`    | разбить строку на `(команда, аргументы)`    |
| `shell.Shell.prompt`        | сформировать приглашение с именем VFS       |
| `shell.Shell.execute`       | выполнить строку, вернуть код завершения    |
| `shell.Shell.repl`          | цикл чтения и выполнения команд             |
| `shell.Shell.run_script`    | выполнить стартовый скрипт                  |
| `shell.Shell.run`           | скрипт, затем диалог; вернуть код эмулятора |
| `commands.cmd_ls`, `cmd_cd` | команды-заглушки                            |
| `commands.cmd_exit`         | команда `exit`                              |

## 3. Сборка и запуск тестов

Сборка не требуется, нужен Python 3.9 или новее.

```bash
./run.sh --vfs demo.zip --script startup/stage2.txt   # запуск
make run ARGS="--script startup/stage2.txt"           # через make
make test         # модульные тесты
make demo         # все скрипты ОС из scripts/
make clean        # удаление служебных файлов
```

Скрипты ОС для тестирования (каждый вызывает эмулятор со всеми
поддерживаемыми параметрами):

| Скрипт                           | Что проверяет                       |
|----------------------------------|-------------------------------------|
| `scripts/test_params.sh`         | все сочетания параметров, `--help`  |
| `scripts/test_params_errors.sh`  | ошибки в параметрах и в скрипте     |
| `scripts/test_startup_script.sh` | выполнение скриптов с разными VFS   |

Тесты без `make`:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

## 4. Примеры использования

Интерактивный сеанс:

```
$ ./run.sh
[debug] vfs: (not set)
[debug] script: (not set)
vfs$ ls -l /home
ls: args=['-l', '/home']
vfs$ cd /tmp  extra
cd: args=['/tmp', 'extra']
vfs$
vfs$ foo bar
foo: command not found
vfs$ exit abc
exit: abc: numeric argument required
vfs$ exit 1 2
exit: too many arguments
vfs$ exit 3
$ echo $?
3
```

Стартовый скрипт с ошибками и последующий диалог:

```
$ ./run.sh --vfs data/demo.zip --script startup/stage2.txt
[debug] vfs: data/demo.zip
[debug] script: startup/stage2.txt
demo$ # Стартовый скрипт этапа 2: команды-заглушки и обработка ошибок.
demo$ # Пустые строки пропускаются, строки с ошибками не прерывают скрипт.
demo$ ls
ls: args=[]
demo$ ls -l /home/user
ls: args=['-l', '/home/user']
demo$ cd /tmp
cd: args=['/tmp']
demo$ cd
cd: args=[]
demo$ # Ошибочные строки: выполнение продолжается
demo$ unknown-command arg1 arg2
unknown-command: command not found
demo$ exit not-a-number
exit: not-a-number: numeric argument required
demo$ exit 1 2
exit: too many arguments
demo$ cd ..  # комментарий в конце строки
cd: args=['..']
demo$ exit 0
```

Ошибки параметров:

```
$ ./run.sh --vfs
usage: emulator [-h] [--vfs PATH] [--script PATH]
emulator: error: argument --vfs: expected one argument
$ ./run.sh --script startup/missing.txt
[debug] vfs: (not set)
[debug] script: startup/missing.txt
emulator: cannot read script 'startup/missing.txt': No such file or directory
```
